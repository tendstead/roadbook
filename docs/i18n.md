# Interface languages

Roadbook supports English and German. On first use, the browser's preferred
language selects German for `de-*`; other languages fall back to English.
Settings → Language switches immediately and stores the override in this browser.
Each browser can use its own language on the same installation.

Language controls interface messages and date, number and currency presentation.
Installation units, currency and timezone remain separate settings. Date inputs
use native browser controls. Editable measurements and money use ungrouped decimal
values; both comma and point decimal input are accepted. CSV date formats and
decimal separators describe the source file and never change with UI language.
User names, notes, filenames and original imported cells remain as entered.

`web/src/lib/i18n.ts` owns the preference and message formatting;
`translations.ts` maps English source messages to German. Use whole messages with
named parameters when word order varies. `format.ts` exposes reactive display
formatters. Keep wire values, enum codes and calculation inputs locale-independent.
Known API validation/warning messages are translated only when displayed; unknown
technical errors remain available verbatim for diagnosis.

The published `@tendstead/ui` 0.1.1 does not expose translation props. Roadbook's
Vite pre-transform in `web/shell-i18n.ts` translates its fixed navigation chrome,
including accessibility labels, without editing the package or sibling repository.
It verifies expected source labels and fails on upstream changes. Replace this
adapter with a supported labels API when the shared package provides one.

Unit tests cover fallback, persistence, reactivity and presentation. Mobile and
desktop browser tests cover both languages, saving exact amounts/category codes,
import review, errors, language persistence and the German mobile drawer.
